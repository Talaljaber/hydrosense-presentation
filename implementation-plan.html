Vibration / Accelerometer GPIO35 — Secondary Supplementary channel. Provides cross-sensor features (Pearson correlation, TDOA). Not fused at model level in v1 — parallel input for analysis and future improvement.

P2

DSP Pipeline on Dataset

Run all 4 signal processing stages on sampled files and produce features_balanced.csv

Write scripts/02_feature_extractor.py — 4-Stage Pipeline
Stage 1 — Pre-processing
  • ▸
    Load each .mat file using scipy.io.loadmat()
  • ▸
    Extract hydrophone channel (primary) and accelerometer channel (secondary) from the loaded struct
  • ▸
    Apply scipy.signal.detrend() to both channels to remove DC offset and linear trends
  • ▸
    Assert that the file's recorded fs matches config.FS — raise an error loudly if there is a mismatch rather than silently proceeding with wrong data
Stage 2 — Pipe Characterisation
  • ▸
    Load MDPE pipe ring files from Pipe_material_characterisation.zip
  • ▸
    Compute Power Spectral Density using scipy.signal.welch() on the pipe characterisation signals
  • ▸
    Use the PSD output to confirm or adjust FILTER_LOW_HZ and FILTER_HIGH_HZ in config.py — identify the frequency band where leak energy concentrates vs. background noise
Stage 3 — Signal Processing
  • ▸
    Design Butterworth bandpass filter: scipy.signal.butter(N, [low, high], btype='band', fs=FS, output='sos') — use SOS (second-order sections) form for numerical stability
  • ▸
    Apply with scipy.signal.sosfiltfilt() — this is zero-phase filtering, no temporal distortion, safe for time-domain feature extraction
  • ▸
    Apply a Hann window to each WINDOW_SIZE frame before FFT to minimize spectral leakage
  • ▸
    Compute FFT using np.fft.rfft() on each windowed frame — use rfft (real FFT) since signal is real-valued, output is half-spectrum
Stage 4 — Feature Extraction
DomainFeatures Extracted
Time Domain RMS, Peak Amplitude, Crest Factor, Kurtosis, Skewness, Zero-Crossing Rate
Frequency Domain Spectral Centroid, Spectral Bandwidth, Spectral Rolloff, Top-5 FFT magnitude bins
Cross-Sensor Pearson Correlation (hydrophone vs. accelerometer), Time Delay of Arrival (TDOA via cross-correlation)
Additional Tasks
  • ▸
    Run the extractor with concurrent.futures.ProcessPoolExecutor(max_workers=4) — parallelize across files to reduce total runtime
  • ▸
    Output: data/features_balanced.csv with a leak label column (0 = normal, 1 = leak)
  • ▸
    Open notebooks/pipeline_validation.ipynb and visually verify all four stages:
    • Plot raw vs. detrended signal — confirm DC removal
    • Plot PSD before and after bandpass filtering — confirm band is correct
    • Plot FFT for a leak window and a normal window — confirm visible frequency difference
    • Plot feature distributions per class — confirm class separation exists before training

P4

ESP32 Firmware & Hardware Assembly

ESP32 streams clean, binary-framed dual-channel acoustic data to the laptop over USB serial at 10 kHz

Firmware — sampler.h
  • ▸
    Use hw_timer_t hardware timer interrupt to trigger ADC reads at exactly config.FS Hz — not a software delay loop, which would drift under CPU load
  • ▸
    Read both GPIO34 (hydrophone) and GPIO35 (vibration sensor) on every timer tick — both channels sampled synchronously
  • ▸
    Store samples in a ping-pong double buffer: while the ISR fills buffer A, the main loop reads from buffer B, then they swap — eliminates read/write conflicts between ISR and main loop without disabling interrupts
Firmware — serial_framer.h
  • ▸
    Pack each sample pair into the binary frame: [0xAA][0xBB][int16 hydro][int16 vib][XOR checksum][0xFF]
  • ▸
    Sync bytes 0xAA 0xBB at the start of every frame allow the laptop-side reader to scan for and re-lock frame alignment automatically after any USB interruption — no manual reset needed
  • ▸
    XOR checksum covers both int16 sample bytes — the laptop drops any frame that fails checksum silently, without throwing an exception or stalling the pipeline
Firmware — hydrosense_esp32.ino (Main Sketch)
  • ▸
    In setup(): initialize both ADC pins in input mode; begin Serial at 921,600 baud
  • ▸
    Start hardware timer at FS Hz — attach ISR from sampler.h
  • ▸
    In loop(): when double-buffer signals that a complete buffer is ready, call serial_framer and transmit all buffered frames over Serial in one burst
Hardware Assembly on Test Rig
  • ▸
    Mount hydrophone in contact with the metal pipe — either water-side (submerged in flow) or pipe-wall contact depending on the hydrophone housing type
  • ▸
    Mount accelerometer / vibration sensor on the pipe exterior — secure with clamp or adhesive to ensure strong mechanical coupling to the pipe wall
  • ▸
    Connect both sensors through the op-amp preamp circuit → ESP32 ADC pins GPIO34 and GPIO35
  • ▸
    Verify signal levels stay within ESP32 ADC range (0 V to 3.3 V strictly) — use a multimeter or oscilloscope before connecting to GPIO; any overvoltage above 3.3 V will permanently damage the ADC input
Calibration & Hardware Recording
  • ▸
    Open laptop serial monitor, confirm 0xAA 0xBB sync bytes are visible in the raw byte stream before running any Python code
  • ▸
    Run normal flow: observe signal amplitude and noise floor on both channels — note baseline RMS level
  • ▸
    Simulate leak (small valve opening, crack, or controlled orifice): confirm a visible signal change appears on the hydrophone channel compared to the normal flow baseline
  • ▸
    Record 2–3 minutes of each condition as .csv using a simple Python logger script — save to data/recorded/normal_flow/ and data/recorded/leak/

P5

Real-Time Edge Hub — Laptop Inference Engine

Python process reads ESP32 stream, runs full DSP + ML pipeline, updates shared result in real time

edge_hub/serial_reader.py — Thread 1
  • ▸
    Open serial port using config.SERIAL_PORT at config.BAUD_RATE
  • ▸
    Scan the incoming byte stream for 0xAA 0xBB sync bytes — re-lock automatically on desync without crashing the thread or requiring a reconnect
  • ▸
    Validate XOR checksum on each parsed frame — drop corrupted frames silently without raising an exception; corrupted frames are simply discarded
  • ▸
    Decode int16 → float32 normalized samples for both channels
  • ▸
    Push decoded samples to collections.deque(maxlen=WINDOW_SIZE * 8) — circular buffer that automatically discards the oldest samples; inherently thread-safe for single-producer single-consumer access
edge_hub/dsp_pipeline.py — Thread 2
  • ▸
    Poll (with a short sleep) until deque contains ≥ WINDOW_SIZE samples before attempting to process
  • ▸
    Pull a WINDOW_SIZE slice advancing by HOP_SIZE (50% overlap) on each iteration — same windowing strategy as training
  • ▸
    Run all 4 DSP stages with identical parameters imported from config.py as used during training — detrend → Butterworth SOS → Hann window → FFT → feature extraction
  • ▸
    Return a np.array of shape (1, n_features) — exact same feature set and column order as the training data in features_balanced.csv
edge_hub/inference_engine.py
  • ▸
    Load model.pkl and scaler.pkl at startup using joblib.load() — loaded once at init time, not on every call
  • ▸
    Accept a feature vector from the DSP pipeline
  • ▸
    Run scaler.transform(features) then model.predict_proba(features_scaled)
  • ▸
    Return result as: {"leak_detected": bool, "confidence": float, "timestamp": str}
  • ▸
    Write the result to a result_store dict protected by threading.Lock() — prevents a race condition where the API server thread reads a partially-written result
Model Re-tune on Hardware Data
  • ▸
    Take the .csv recordings from Phase 4 stored in data/recorded/
  • ▸
    Run the same 02_feature_extractor.py on the hardware recordings to extract features in the same format as the Southampton data
  • ▸
    Append the extracted hardware features to features_balanced.csv and retrain the model using 03_train_model.py
  • ▸
    Verify that inference accuracy improves on test conditions matching the real metal pipe rig — compare before/after confusion matrices
main.py (partially wired) prints live classification results to console continuously. Leak simulation consistently causes leak_detected: true above the confidence threshold.

EndpointMethodReturns

Risk Register
RiskLikelihoodImpactMitigation
Model trained on MDPE plastic data underperforms on metal pipe rig High High Expected. Collect hardware recordings in Phase 4 and retrain. Treat Southampton data as bootstrap only — not the final model.
ESP32 ADC noise or signal saturation Medium High Use GPIO34–39 (input-only pins, most linear ADC). Add hardware RC low-pass before ADC pin. Verify voltage range with oscilloscope or multimeter before connecting.
Serial desync during live demo Medium High Sync byte sequence 0xAA 0xBB + auto-relock loop in serial_reader.py. System recovers within one dropped frame automatically without user intervention.
Feature mismatch between training and inference Medium Critical config.py is the single source of truth. Training and inference both import from it. Never hardcode filter or window values in two places — a mismatch silently degrades accuracy.
Laptop firewall blocks browser SSE connection Low Medium Test CORS and local firewall settings in Phase 6. Use a mobile hotspot to put both devices on the same LAN if the venue network blocks local connections.
Hardware failure at presentation Low Critical --demo-mode flag in main.py replays a pre-recorded hardware session at real timing — dashboard is indistinguishable from live. Screen recording as absolute final failsafe.
